<original_problem_statement>
The initial request was to build **FITTR**, a comprehensive, location-based fitness social platform. The app's goal was to connect users for workouts and training sessions, similar to Uber's on-demand model but for fitness. Key features included an advanced user profile system, an intelligent matching engine, session management with an AI-powered workout generator, a social feed, a rating system, a marketplace for wellness products, and robust safety features like an emergency SOS. The specified tech stack included Next.js, PostgreSQL (Supabase), and Prisma.

However, after an initial version was built, the user provided a new set of app flow images for an app called **GOWITHME**. The user clarified that they want the same core functionality as FITTR but with the completely different GOWITHME branding, visual design, and a user experience that is a hybrid of **Uber (map-centric, quick connections) and Facebook (social feed, community)**. The agent was instructed to keep the existing backend architecture where possible and focus on rebuilding the frontend to match the new GOWITHME design.

**PRODUCT REQUIREMENTS:**
- **App Concept:** A social platform named GOWITHME for connecting people for various activities (fitness, coffee, cinema, etc.).
- **Core UX:** A hybrid of Uber's map-based connection model and Facebook's social community features.
- **Visual Design:** A deep blue theme (#1a1aff) with glowing white text, purple accent buttons (#4a3aff), and a modern, card-based UI.
- **Key Features:**
    - Map-based companion finding and location sharing.
    - Activity selection grid.
    - Real-time activity alerts.
    - Social feed and messaging.
    - Wellness e-commerce store.
    - User profiles with ratings, calendar, and availability.
    - All backend functionality from the original FITTR spec (matching, sessions, etc.) should be preserved.
